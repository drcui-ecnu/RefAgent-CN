# Reproducibility and relation to the frozen system

The `paper-release` tag identifies the original paper-associated public snapshot. Subsequent `main` updates simplify user documentation and expose configurable deployment endpoints through `REFAGENT_API_KEY`, `REFAGENT_BASE_URL`, and `REFAGENT_MODEL`. These options do not change the frozen experiment. The legacy `DEEPSEEK_API_KEY` configuration remains supported when no custom configuration is supplied. Provider compatibility is not universal; configuration routing is tested with mocked requests, not fresh model inference.

The parser, JournalKB, exact verified Title KB, source-aware hybrid, HTTP client, PDF reader and citation renderer were mechanically extracted from v3.9.0. Only package-relative imports and English-only comment/docstring cleanup were applied to those modules. Executable AST equivalence is checked after removing docstrings and normalizing import levels; source checksums are recorded in `core_source_map.csv`. The public wrapper and small bilingual interface are new portability layers, not the old legacy UI.

The historical formal run read 300 Chinese references from Excel; PDF extraction was not part of that experiment. Each record had one shared generation for LLM-only and Full. Calls/success/failures/retries: 300/300/0/0. Explicit payload: model, messages, temperature=0.2, max_tokens=512, stream=false. top_p, seed and penalties were not sent; effective server values and provider model revision are unknown. Critic, candidate selection, semantic few-shot and online search were disabled.

The full historical Title KB contains 3,372 records. Formal matching keys are normalized Chinese title + Chinese journal + year. A deterministic formal mask excluded overlapping records, leaving 3,360; masks are not optional when reconstructing the held-out experiment. Regular usage can accept a full permitted snapshot; that changes resource coverage and is not the masked benchmark condition.

The hybrid accepts exact Journal KB mappings; the resolver's fuzzy branch is not adopted. No independent alias_cn branch exists. The Title KB accepts only verified, official exact-key records. Generated fallback fields remain generated and review-required. A single upstream response is still required in the historical architecture; a KB hit is not evidence that an upstream API request was skipped.

The evaluator extracts unchanged NEM/numeric/page normalization functions from the final scoring script and identity helpers from final author rescoring. Author identity is order-sensitive and uses the Gold-observable surname and initials. The frozen final implementation permits observable initials to occur in order in a romanized given-name string, with the first at its start (e.g. concatenated given names); no surname aliases or correction dictionary is added. Strict form remains separate. English Title NEM is NFKC, quote/dash cleanup, collapsed whitespace, casefold and removal of one final period. chrF++ uses sacrebleu 2.6.0 `CHRF(word_order=2)`. COMET actually loads a user-supplied checkpoint, uses src/mt/ref and CPU batch size 8; no score-cache printing substitutes for computation.

Formal source snapshots, Gold and responses remain local pending permissions. The public package can demonstrate processing and evaluate suitably licensed user-supplied data, but cannot reproduce all paper numbers using the synthetic fixture. Complete environment versions for the historical API run were not logged; the release testing environment is documented separately and is not relabeled as the historical environment. Stochastic online regeneration is not guaranteed.

Offline reconstruction with permitted formal assets: verify hashes → load sealed shared responses → instantiate the preserved hybrid with Journal KB3075 and formal masked Title KB3360 → derive LLM-only/Full fields → flatten predictions to the evaluator schema → score separately against Gold. Never rerun online generation merely to reproduce a sealed result.

PDF ingestion prefers PyMuPDF and attempts selected-page pdftotext fallback. Default PyMuPDF selection is first/last five pages, deduplicated. The pdftotext fallback does not add an overlapping back range on 6–9-page documents and only reads the front when page count is unknown. Chinese text-layer and layout heuristics can fail; scanning requires external OCR, not built-in processing. English-title extraction is heuristic, not a new translation.

The Institution/Publisher/Organization `EntityKB` class is retained. The formal journal-reference hybrid does not call those optional entity resources; callers can use them for other record types. They are not conflated with JournalKB.
